# AI 활용 기록

## 어디까지 도움을 받았는가

범위가 도중에 바뀌었다.

| 단계 | 작성 |
|---|---|
| Socket RAII, 에코 서버, 패킷 직렬화 | 직접 작성. AI는 개념 설명·문법 질문·리뷰·에러 해석 |
| tick 루프, World, AOI, 봇, 측정 | 제출 기한이 촉박해져 AI가 코드를 작성하고 검토·실행하는 방식으로 전환 |
| 커밋 메시지 | AI 초안, 확인 후 커밋 |
| 설계 결정과 측정 조건 | 구현 전에 `docs/decisions/`로 확정한 것을 따랐다 |

측정은 전부 본인 환경에서 실행한 결과다.

## 기각한 제안

**AOI를 원(view radius)으로 잡기** — 대상 게임은 카메라가 고정된 2D라 실제 가시 영역이
직사각형이다. 정사각형으로 바꾸니 broad phase의 셀과 모양이 맞아 precision이 34.9%에서
44.4%로 오르고, narrow phase에서 곱셈도 사라졌다.

**패킷 길이를 4의 배수로 유지하는 불변식** — 수신 버퍼에서 바로 캐스팅할 수 있게 되지만
사람이 지켜야 유지되는 규약이라 접었다. `docs/decisions/02` 참조.

**Docker + epoll로 전환** — 처음 받은 근거는 "VM의 네트워크 스택 때문에 측정이 오염된다"였는데,
서버와 봇을 모두 VM 안에서 돌리면 트래픽이 VM 경계를 넘지 않아 해당하지 않는다.
근거가 틀렸다. 실제로 접은 이유는 논블로킹 I/O 학습 비용이다.

## 측정 과정에서 바로잡은 것

**naive와 grid만 비교해서는 AOI 효과가 잡히지 않았다.** 전송 바이트가 493,868 대 493,721로
거의 같게 나왔는데, naive에도 narrow phase가 있어 이미 화면 밖은 보내지 않고 있었기
때문이다. 두 모드 비교는 broad phase 비용만 재고 있었다.

필터 없이 전원에게 보내는 `broadcast` 모드를 기준선으로 추가해 둘을 분리했다.
전송량을 줄이는 것은 AOI 개념이고, 공간 분할이 줄이는 것은 판정에 이르기까지의 후보 수다.

**계측을 스스로 검증했다.** 서버가 센 K와 봇이 받아 해석한 visible 수가 일치하는지,
sequence에 구멍이 없는지를 측정할 때마다 확인했다.
