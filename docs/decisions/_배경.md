# 결정의 배경 자료

**⚠️ 이 파일은 참고용이다. 그대로 베껴 결정 문서를 만들지 말 것.**

이전 세션 논의에서 나온 근거들이다. 결정 문서는 본인 문장으로 다시 써야 하고,
납득되지 않는 항목은 그 자리에서 반박하고 다시 정하면 된다.

## 1. I/O 모델 — 클라이언트당 스레드 (blocking)

**기각한 대안**: kqueue 이벤트 루프, Docker + epoll

**명분 (기간과 무관하게 성립)**
- 이벤트 루프는 단일 스레드가 자연스러운데, 그러면 공유 상태 동시 접근이 구조적으로
  일어나지 않아 **아이템 복사 버그를 재현할 수 없다.** 두 주제 중 하나가 사라진다
- AOI 절감률은 I/O 다중화 방식과 **독립**이다. 관심 변수가 아닌 것은 단순하게 고정한다

**솔직히 인정할 부분**: 기간도 요인이었다. "시간이 없어서 아니냐"고 물으면 인정하고
위 논리로 잇는다. 부인하면 더 나쁘다.

**대가**: 스레드-per-클라이언트가 "학부 과제 수준"으로 읽힐 위험이 실재한다.
완화책은 (1) 송신 큐로 게임 로직과 네트워크를 분리한 설계, (2) 한계를 숫자로 적은 README,
(3) **면접 전까지 이벤트 루프 원리를 설명할 수 있는 상태** — 레벨/엣지 트리거 차이,
부분 쓰기 시 쓰기 이벤트 처리, 왜 스레드보다 많은 접속을 감당하는지.

## 2. 패킷 형식 — 고정 헤더 + 명시적 직렬화

**결정적 근거**: AOI 스냅샷은 본질적으로 **가변 길이**다(주변 인원이 매 tick 다름).
구조체 통째 전송으로는 표현 자체가 불가능하다. `std::vector`를 `memcpy`하면 힙 포인터
값이 전송된다.

**부차 근거**
- 패딩: 값 9바이트짜리 구조체가 12바이트로 나가고, 그 3바이트는 초기화되지 않은 메모리다
  (실측 확인). 정보 유출 경로이자 33% 낭비
- 정렬: 수신 버퍼는 임의 오프셋에서 시작하므로 캐스팅이 UB다 (UBSan으로 실측 확인).
  `memcpy` 역직렬화는 이 문제가 아예 없다
- 엔디안: 구조체 전송은 네이티브 순서. 고른 게 아니라 물려받은 것
- 필드 추가 시 `sizeof`가 바뀌어 양쪽 동시 재빌드 강제

**패딩은 메모리용 장치다.** 전선 위에서는 전제(시작 주소 정렬)가 성립하지 않아 비용만 남는다.

## 3. AOI 전략 — uniform grid

| 대안 | 기각 사유 |
|---|---|
| spatial hashing | 맵이 작고 유계라 이점 없음. 해시 조회 비용과 나쁜 cache locality만 남음 |
| quadtree | 동적 entity에 재구성 비용. 매 tick 전원이 움직이면 분할·병합이 격자 순회보다 비쌀 수 있음. 원래 정적 지형·충돌용 자료구조 |
| interest list | grid 위에 얹는 추가 layer. grid가 선행돼야 함 → next step |

**cell size = a인 이유**: 세 요소의 균형. 셀을 줄이면 precision은 오르지만(44%→50%→62%)
방문 셀이 4배씩 늘고(9→25→81) cell transition 빈도도 올라 border thrashing에 취약해진다.

## 4. 거래 — tick 밖 병렬 + 락

**대안**: tick 스레드로 직렬화하면 락 없이도 원자성이 보장되고 데드락이 불가능하다.
실무 게임 서버에서 흔한 선택이다.

**그럼에도 병렬을 택한 근거**: 실제 서비스에서 거래에는 검증·영속화·로그가 붙고,
그걸 tick 스레드에서 하면 게임 루프가 밀린다. tick이 `send`를 직접 하지 않는 것과 같은 원리다.

**락은 목적이 아니라 수단이다.** 목적은 atomicity.

## 5. 그 밖에

- **송신 큐 초과 시 오래된 스냅샷 폐기** — 스냅샷이 전체 상태라 이전 것 없이 해석 가능하다.
  델타 방식이었다면 중간을 버릴 수 없어 다른 정책이 필요했다
- **sequence 필드** — TCP라 순서 보장 목적이 아니다. **송수신 대조로 측정을 검증하고,
  큐에서 버려진 스냅샷을 추적**하기 위한 것
- **naive에서도 narrow phase를 돌린다** — 안 그러면 AOI 효과와 필터링 효과가 섞인다
