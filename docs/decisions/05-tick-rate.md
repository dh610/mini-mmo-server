# 틱레이트 — 20Hz

## 무엇을 정했나

기본 20Hz(예산 50,000μs). `--tick`으로 바꿀 수 있다.

## 왜

**AOI의 절감 비율은 틱레이트와 무관하다.** AOI가 줄이는 것은 tick 한 번당 수신자 수이고,
tick 수는 거기에 곱해지는 상수다. 60Hz로 올려도 감소율은 같고 절대 패킷 수만 커 보인다.
숫자를 크게 만들려고 틱을 올리는 것은 이득 없이 조작만 되는 일이다.

그래서 **결론이 바뀌지 않는 범위에서 장르에 맞는 값**을 골랐다. 2D MMORPG는 대체로
10~30Hz대이고, 경쟁 FPS가 60Hz 이상이다. 착안한 게임에서 60Hz가 필요할 이유가 없다.

## 실제로 바뀌는 것

틱 예산이 작을수록 tick overrun이 일찍 나타난다. 즉 스레드-per-클라이언트 모델의
한계 지점이 틱레이트에 직접 좌우된다.

측정 결과 20Hz에서는 400봇까지 예산의 4.5%만 썼고 overrun은 0회였다.
**이 규모에서는 틱레이트를 올려도 여유가 있었다는 뜻이고, 동시에 이 측정으로는
모델의 한계 지점을 찾지 못했다는 뜻이기도 하다.**

## 포기하는 것

20Hz는 위치 갱신 간격이 50ms다. 실제 게임이라면 클라이언트에서 보간이나 예측이
필요한 수준이고, 이 프로젝트에는 그래픽 클라이언트가 없어 그 영향을 확인하지 않았다.
